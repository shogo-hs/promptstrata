# 0009. バージョン管理の方針

- 状態: 採用
- 日付: 2026-08-23

## 文脈

外部に配布するライブラリなので、利用者が何を安定と期待してよいかを決めておく必要があります。
版が `pyproject.toml` の `version` と `src/promptstrata/__init__.py` の `__version__` の2箇所に
あり、食い違いうる状態でした。

## 決定

- **版の正本**: `pyproject.toml` の `version` ただ1つ。`__version__` は
  `importlib.metadata.version("promptstrata")` で読み、値を書き写しません。
- **番号の付け方**: SemVer に従います。ただし 0.x のあいだは minor（例: 0.2.0）で破壊的変更が
  入りえます。1.0 以降は破壊的変更を major に限ります。
- **公開 API に含めるもの**（変えたら破壊的変更）
  - `PromptSet` / `BuiltPrompt` / `SourceRef` と、それらのフィールド・メソッドの型
  - 例外（`PromptStrataError` / `LayerFileError` / `BuildError`）
  - レイヤーの型（`Role` / `Vocabulary` / `Governance` / `Channel` / `Procedure` とその中の型）
  - レイヤー YAML のスキーマ（キー名・必須かどうか）
  - CLI のサブコマンドとオプション（`build` / `lint` / `--channel` / `--procedure` / `--var`）
  - 合成後のプロンプト本文の文面
- **CHANGELOG**: `CHANGELOG.md` に Keep a Changelog 形式で日本語で記録します。
- **リリース手順**: `README.md` の「バージョンとリリース」節と `CLAUDE.md` に記載します。

## 理由

とくに「合成後のプロンプト本文の文面」を公開 API に含める理由を書きます。このライブラリの
成果物はコードではなく文字列で、その文字列がそのまま利用者の LLM に渡ります。見出しの文言や
節の順序を静かに変えると、利用者は自分のエージェントの振る舞いが変わった理由を追えません。
`built.fingerprint` は本文の sha256 から出しているため文面が変わればすべて変わり、過去の
応対ログと突き合わせることもできなくなります。誤字の修正のように意味が変わらない変更は
patch で構いませんが、見出しや節の順序、文言の意味が変わる変更は破壊的変更として扱います。

版の正本を1つにするのは、2箇所に同じ値を置くと必ず食い違うためです。`importlib.metadata` は
インストール済みのパッケージのメタデータを読む標準ライブラリの機能で、これ以上の仕組みは
要りません。

0.x で minor に破壊的変更を許すのは、初期の公開 API がまだ固まっていないためです。1.0 を
「利用者に安定を約束する」区切りとして扱います。

## 結果

文面を直すだけでも版を上げる必要があり、細かい言い回しの改善はまとめて出すことになります。
反面、利用者は版を固定しておけば文面が変わらないと期待できます。0.x のあいだは minor の
上げ幅が大きく見えることがありますが、SemVer の 0.x に対する一般的な解釈のとおりです。
