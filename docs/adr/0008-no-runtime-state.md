# 0008. 会話中に確定した事実の反映はスコープ外とする

- 状態: 採用
- 日付: 2026-08-23
- 置き換え: [0006](0006-static-and-mutable-split.md)

## 文脈

0006 で「固定部（`built.text`）と可変部（`built.state(facts)`）を分け、可変部をシステム
プロンプトの末尾に置く」と決めました。この前提が誤っていました。

プロンプトキャッシュは `tools` → `system` → `messages` の順の前方一致で効きます。Anthropic の
仕様には "Changes at each level invalidate that level and all subsequent levels" と明記されて
います（[Prompt caching](https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching)）。
システムプロンプトの末尾を毎ターン書き換えると、守れるのは固定部だけで、それ以降の会話履歴の
キャッシュは丸ごと落ちます。会話が伸びるほど失うものが大きく、キャッシュを守るという狙いと
逆の結果になります。

## 決定

- `BuiltPrompt` に `state()` を持たせません。会話中に確定した事実の整形と配置は、呼び出し側の
  責務とします。
- 0006 の前半（`built.text` をビルド時に一度だけ合成し、会話中に作り直さない）は維持します。
  撤回するのは後半（可変部を持ち、システムプロンプトの末尾に置く）だけです。
- README には、書き戻さない理由と、足すなら `messages` 側であることを残します。存在しない API を
  コード例に書かないよう、README のコード例はテストで実行します（`tests/test_readme.py`）。
- レイヤー YAML に会話中の動的な事実を書く例は足しません。レイヤーに書くのは事実そのものではなく
  事実の扱い方（「確認済みと明示された事実だけを既知として扱う」など）です。

## 理由

- `state()` の中身は `dict` を箇条書きに整形するだけで、レイヤー YAML に一切依存しません。
  このライブラリ固有の価値が何も乗っておらず、0007 で引いた線の外側にあります。
- 置き場所は呼び出し側の `messages` の組み方に依存します。基盤ごとに経路が違い、Pipecat は
  `LLMMessagesAppendFrame` でメッセージ履歴に追記する方法を案内し、システムメッセージを更新の
  たびに書き換える方法は信頼性が低いと明記しています。LiveKit Agents は chat context の末尾、
  Retell と Vapi は dynamic variables やツールの戻り値が経路です。1つの文字列整形はそのうち
  1つにしか馴染みません。
- `built.text` と `built.state()` を同じクラスに並べると「対で使うもの」に見え、システム
  プロンプトへの連結を誘発します。実際にこの誤りを一度書きました。
- 客が口頭で名乗った事実はモデルが会話履歴から読めます。書き戻す価値があるのは「裏が取れた」
  という印が要る事実だけで、それも `messages` 側で足ります。

## 結果

公開 API が1つ減り、境界が「レイヤー YAML から1本の文字列を作る」に揃いました。反面、事実を
`messages` に足す配線は利用者が書くことになります。基盤ごとに形が違うので、README では経路の
例を示すにとどめます。

古い事実の節が会話履歴に積み上がる問題は残ります。消すとそこから先のキャッシュが落ちるので
消せません。どれが最新かはプロンプト文面の指示に依存し、コードで強制はできません。レイヤー側に
「会話履歴の最後のものを最新とする」規律を書いて対処します。
