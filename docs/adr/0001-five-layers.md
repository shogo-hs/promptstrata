# 0001. レイヤーを5種にする

- 状態: 採用
- 日付: 2026-08-22

## 文脈

CS エージェントのシステムプロンプトは、企業ごとの振る舞い・サービス名の語彙・禁止事項・
チャネル固有の制約・業務手順が1本の巨大な文字列に混ざり、誰も全体を把握できなくなる。
当初の案は役割・語彙・ガバナンス・チャネルの4層だった。

## 決定

- 4層に**手順（procedure）**を足して5層にする。
- 構成はロール1・語彙1・ガバナンス1・チャネルN・手順Nとする。

## 理由

「返金の受付手順」「本人確認の手順」は役割でも禁止事項でもない。分離しないとロールに
溜まって読めなくなる。商用の Decagon は Agent Operating Procedures という名前でこの層を
製品の中心に据えており、CS の業務では独立した層になるだけの分量がある。

## 結果

手順が増えてもロールが太らない。反面、書き手は「これはロールか手順か」を判断する
必要が出る。
